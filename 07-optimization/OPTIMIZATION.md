# 优化方案（基于接管首班的真实数据）

> 结论先行：**这套体系的产能是过剩的，分发与转化是短缺的。** 内容线跑了 4 个月、产出 44 篇博客 / 119 个页面，换来 28 天 27 次点击、0 新询盘。继续加产能不会改善结果；把同样的力气挪到「标题与分发的转化」上，同样的投入能拿到 2 倍以上的点击。
>
> 本文所有数字来自 `08-execution/` 下可复跑的实测文件，不是估计。

> **重要限定（我一度想错，已更正）**：不能把这些归因为「低意图长尾稀释」。
> 实测：business-plan 页 271 展示里，**可见查询只覆盖 68 展示（25%），其余 203（75%）被 GSC 匿名化**；而这 68 展示的可见查询**100% 是商业意图**（business plan / business case / revenue model），且 0 点击。
> 所以：① 意图稀释的假设无法被数据支持；② 真正可确认的是「在 p10–32 的商业意图词上拿不到点击」；③ 剩下 75% 展示什么词，GSC 不告诉我们——**这是低成本站点的硬约束，任何 query 级归因都不完整**。
> 因此 P0-1 的正确做法不是「筛掉低意图词」，而是：**先修那 3 个位次已进前 10 却 0 点击的页面（nevi p8.7 / revenue-share p5.6 / home p4.8）**——这几个的位置足够好，0 点击只能是 SERP 呈现问题，可诊断、可验证。

**算一笔账**：这 872 展示如果做到 3% CTR = **+26 次点击/28 天**，相对现有 27 次是 **+96%**。
而按历史边际，**再写 8 篇新文章 ≈ +5 次点击**（0.61 × 8）。
→ **改 8 个标题的收益是写 8 篇新文的 5 倍，成本不到 1/20。** 这是全案最高 ROI 的动作。

## 二、优化动作清单（按 ROI 排序）

### P0-1 修 8 个零点击页面的 title/meta（最高 ROI）
- **做什么**：逐页重写 title 与 meta description。规则：数字前置、商业意图词前置、把「免费/2026/清单/$区间」这类钩子放前 40 字。
- **不做什么**：不动正文、不动结构（避免触发事实门与版面回归）。
- **预期**：872 展示 × 3% CTR ≈ +26 点击/28 天（+96%）。
- **验收**：改后 14 天，这 8 页合计 CTR ≥ 3%，合计点击 ≥ 12。
- **风险**：`/agents/` 与位次 >40 的 3 页（apartment-condo / dealership-india / operating-cost）位次太深，改标题收益有限，**优先级排后**；先做 p5.6、p8.7、p20.2 这三页。
- **执行方式**：按 R9 走 `seo/` 分支 + Gatekeeper；只改 title/meta/og，属于 Gatekeeper 白名单内的 `site/blog/*.html`。

### P0-2 恢复社区分发（R5 重新设岗）
- **做什么**：Quora 恢复日更 1 条（带链接 ≤3/周），Reddit 按养号纪律每周 2 帖。
- **为什么**：唯一验证过当天见效的渠道；成本近 0。
- **验收**：每周 ≥5 条回答、带链接 ≥2 条；30 天后 Quora 引荐会话 ≥50（GA4 referral）。
- **前置**：需要浏览器（WebBridge）。按 R6 不做第三方后台，但 Quora 发帖属于「内容平台发布」不是「后台配置」，**需要用户明确授权**这一项例外。

### P0-3 外链：从「发 13 家等回复」改成「先建可被引用的资产」
- **现状**：13 家全部无回复，0 落地。继续发信是重复无效动作。
- **做什么**：暂停新 pitch 两周；改为「数据资产」路线——把站内已有数据做成可引用素材（22 国 100+ 客户、NEVI 补贴金额、LCFS 价格区间、BESS 成本矩阵），供 Qwoted / Source of Sources 的记者请求直接取用（这两个账号已就绪，且是被动等请求，不需要发信）。
- **验收**：30 天内至少回复 10 条记者 query，获得 ≥1 条引用/提及。
- **为什么**：现状是「主动冷邮件 0 回复」，而「被动记者平台」已注册好却没用过。

### P1-1 内容降频：5 篇/周 → 2 篇/周
- **理由**：44 篇存量、边际 0.61 点击/篇；继续日更只是增加维护面（每篇都要过门禁、要索引、要内链）。
- **省下的 3 档/周**：投到 P0-1（改标题）、P0-2（社区）、内链补强。
- **保留**：长尾词簇仍需覆盖时按需插队，不排固定日更。

### P1-2 合并低频情报线
- GEO 优化师（周四）、AI 可见度监测员（双周四）、竞品情报分析员（周三）三条线每周各跑一次，但产出没有进入选题决策（10-29 起连续漏跑/失败也没影响任何后续动作）。

- **省下**：约 3 档/周。

## 三、技能层优化

### 现状
- 源库：`.agents/skills` **137** 个目录 + `.claude/skills` 另有 **9** 个真实独立技能（其余为符号链接）≈ **146** 个唯一技能，550+ 文件 / 4.3MB。
- 处置依据：`营销团队v2-花名册与技能整合.md` 只处置了 **79** 个（在岗 41 / 合并 10 / 归档 28）。79 → 137 新增的 **58 个没有任何处置结论**。
- 逐技能清单与质量门见 `01-inventory/skills-*.md`，合并映射见 `02-skills/_MERGE-MAP.md`。

### 优化原则
1. **在岗集 ≤ 45**。技能目录越大，agent 检索命中率越低、上下文越容易被无关方法论污染。当前 146 个里真正会被调用的按 v2 花名册只有 41 个。
2. **按「预算约束」整组归档，不按技能好坏归档**：
   - 付费媒体全组（`cm-google-ads` / `cm-facebook-ads` / `cm-linkedin-ads` / `cm-tiktok-ads` / `cm-cross-platform-audit` / `cm-wasted-spend-finder` / `cm-competitor-ads-analyst` / `sa-ads-*` / `ads` / `ad-creative` / `utm-attribution-strategy` 等）→ **整组归档**。理由是 R3 硬规则「$500/月 100% 投有机，不设付费媒体岗」，这些技能在本项目里**结构上不可能被调用**，留着只会稀释检索。
   - 产品形态不符组：`aso`（无 App）、`paywalls`（无订阅）、`sms`（无短信计划）→ 归档。
   - 留存/客户成功组：`churn-prevention` / `referrals` / `onboarding` / `signup` / `revops` / `sales-enablement` / `client-onboarding-proposal` / `co-marketing` → 暂归档，客户规模化后重启。
3. **合并同义**：v2 已列 10 组合并（`seo-audit`→`seo-technical-audit`、`schema`→`seo-schema`、`keywords`→`seo-keyword-cluster`、`cro-auditor`→`cro`、`copy-editing`→`copywriting`、`social-post-writer`→`social`、`emails`→`lead-magnets`、`ai-seo`→`seo-geo`、`seo-analyzer`/`technical-seo-audit`→`seo-technical-audit`）。新增 58 个里若发现同类重复，按同样规则并入。
4. **补 3 个项目专用技能（当前缺）**：
   - `anari-fact-guard`：事实库口径 + 禁用表述清单（22 国规则、不点名竞品、功率口径）+ `check-facts.js` 的关系。
   - `anari-gsc-api`：官方 API 取数口径（页面维度、匿名化陷阱、URL Inspection 用法）。→ 实际以 `scripts/` + `AGENTS.md` 呈现，不必做成 skill。
   - `anari-gatekeeper`：PR 分支命名、白名单、MIRRORS 手法的操作手册。→ 同上。

### 结论（与已交付的 `02-skills/_MERGE-MAP.md` 对齐）

接管时实际落地的处置是：**146 个技能 → active 84 / archived 41 / merged 21**（见 `02-skills/_manifest.json` 的 `statusSummary`）。付费媒体全组已按 R3 归档，v2 的 10 组合并已执行，6 个 Eric Siu 技能补齐了缺失的 frontmatter（源库本身没有，属于带病移植，已修）。

**我的进一步建议（尚未执行，等你决定）**：把 active 从 84 压到 ≤45。
- 理由：84 个里真正有排期、会被主动调用的按 `_SCHEDULE.json` 只有约 40 个；其余 44 个属于「保留但不会被排期调用」。技能目录越大，agent 检索时被无关方法论污染的概率越高。
- 做法：不是删，而是把「保留但无排期」的 44 个从 `active` 降级为 `standby`（新增一个状态值），检索时默认只查 active。
- 风险：低。任何 skill 文件都还在，需要时改一个字段就能启用。

**这一条不是必须做的**。84/41/21 的处置本身已经比源库的「137 个一把梭」好很多；压缩到 45 是锦上添花，收益在于减少 agent 选错方法的概率，不是功能性的。

## 六、与「30 询盘/月」目标的距离（诚实版）

- 现状：28 天 185 个 GA4 session（`session_start`），27 次搜索点击。
- 目标：30 询盘/月。按 B2B 站 1–2% 询盘转化率，需要 **1,500–3,000 访问/月**。
- **差距：约 10–16 倍流量。**
- 单靠内容：44 篇 → 27 点击/28 天，即便线性外推到 10 倍点击需要约 440 篇，按当前速度需 5–8 年。**这条路在数学上不成立。**
- 结论：30 询盘/月不可能由纯 SEO 达成。原 `anari-daily-ops-plan.md` 第一节其实已经算出了这个结论（「纯 SEO 爬到那个量级要 6-12 个月——太慢」），也给出了答案（Quora/社区/目录为先）。**方案没错，是执行在 10-16 之后停了。**
- → 重建优先级应该是：**分发（社区/目录/记者平台）> 转化（标题/落地页）> 内容产能**。当前的排期恰好是反的。
